# ممیزی و برنامه مرحله‌ای ATRA (فقط برنامه، بدون تغییر)

## ۱. وضعیت واقعی معماری و فایل‌ها (بررسی‌شده در کد)
- چارچوب: TanStack Start + React 19 + Vite 7، اجرا روی Cloudflare Worker. Vitest برای آزمون.
- فقط یک صفحه واقعی (`/`)؛ جابه‌جایی بین صفحه‌ها با حالت داخلی است، نه آدرس جدا.
- صفحه‌ها هرکدام در فایل جدا در `src/components/atra/`: داشبورد، مشتریان، پرونده مشتری، سفارش‌ها، وظایف، دستیار.
- قوانین وضعیت سفارش در `order-workflow.ts` با ۱۳ آزمون.
- داده: فقط در مرورگر همان دستگاه (localStorage). بدون سرور، دیتابیس، ورود، نقش یا پشتیبان.
- ظاهر فارسی RTL با فونت Vazirmatn و کلاس‌های CSS اختصاصی ATRA حفظ شده است.

## ۲. واقعی در برابر نمایشی
- واقعی (محلی): افزودن/ویرایش/جستجوی مشتری، ثبت سفارش و تغییر وضعیت طبق قوانین، افزودن و تیک‌زدن وظیفه.
- نمایشی: همه اعداد داشبورد، اغلب بخش‌های پرونده مشتری، دستیار هوشمند (پاسخ ثابت)، اعلان‌ها، جستجوی بالا، تنظیمات، مسیر فروش.
- وجود ندارد: محصولات، پیش‌فاکتور، تأیید قیمت، شکایت/گارانتی، مطالبات، کاربران، ورود Excel، پشتیبان.
- مبلغ‌ها متن هستند («۴۲۰ میلیون») و تاریخ‌ها متن فارسی؛ قابل جمع و مرتب‌سازی نیستند.

## ۳. اختلاف Lovable و GitHub
- مخزن فعلی فقط مخزن داخلی Lovable است؛ هیچ اتصال GitHub در این پروژه دیده نمی‌شود. پوشه `.github` هم ندارد.
- پس اختلافی قابل تشخیص نیست. اگر مخزن GitHub جداگانه‌ای از نسخه Figma Make دارید، با این پروژه همگام نیست. اتصال GitHub فقط یک مخزن جدید می‌سازد و به مخزن موجود وصل نمی‌شود.

## ۴. معماری پیشنهادی کم‌هزینه
گزینه A (پیشنهادی): Lovable Cloud (همان Postgres/Supabase مدیریت‌شده)
- ورود استاندارد آماده (ایمیل/رمز، بدون رمزنگاری دست‌ساز)، نقش‌ها در جدول جدا، قوانین دسترسی در خود دیتابیس (RLS)، ذخیره فایل.
- هزینه: ماهانه سهمیه رایگان کوچک دارد؛ بیشتر از آن از اعتبار کم می‌شود. اگر اعتبار تمام شود، دیتابیس متوقف می‌شود.
- ریسک: دسترسی از ایران به سرویس‌های خارجی ممکن است کند یا مسدود باشد؛ باید آزمایش شود.

گزینه B: Supabase شخصی خودتان (حساب جدا)
- کنترل کامل و قابل انتقال؛ هزینه و مدیریت با خودتان؛ پرداخت خارجی لازم است.

گزینه C: فقط محلی (مرورگر) + خروجی فایل
- رایگان، ولی چندکاربره نیست و امنیت واقعی ندارد. فقط برای مرحله آزمایشی.

اجزای مشترک:
- PWA: فقط «نصب روی صفحه اصلی» (بدون حالت آفلاین در ابتدا) تا مشکل نسخه قدیمی پیش نیاید.
- پشتیبان مستقل: خروجی دوره‌ای Excel/JSON که مدیر دانلود و جدا نگه می‌دارد، به‌علاوه پشتیبان خود دیتابیس.
- ورود Excel: بارگذاری ← پیش‌نمایش ← نمایش خطاها ← تأیید انسانی ← ثبت. محک فقط از طریق فایل Excel و فقط‌خواندنی.
- واحد نمایش تومان؛ ذخیره به‌صورت عدد صحیح تومان.

## ۵. ترتیب مراحل و معیار پذیرش
1. آدرس جدا برای هر صفحه — همه صفحه‌ها با لینک مستقیم باز شوند؛ تصویرها پیکسلی یکسان.
2. مدل داده: مبلغ عددی تومان، تاریخ واقعی با نمایش شمسی، اتصال وظیفه به شناسه مشتری — آزمون‌های تبدیل تومان/شمسی و محاسبه «عقب‌افتاده» پاس شوند.
3. نصب روی صفحه اصلی (PWA ساده) — روی Android و Windows قابل نصب؛ پیش‌نمایش بدون مشکل.
4. فعال‌سازی Lovable Cloud (پس از تأیید) + جدول‌ها + ورود — کاربر بدون ورود هیچ داده‌ای نبیند؛ آزمون دسترسی.
5. نقش‌ها و مجوز سمت دیتابیس — فروشنده نتواند قیمت تأیید یا سفارش لغو کند؛ آزمون برای هر قانون.
6. انتقال داده محلی به دیتابیس با پیش‌نمایش — هیچ رکوردی گم نشود؛ شمارش قبل/بعد برابر.
7. ورود Excel مشتری/محصول با بررسی انسانی — ردیف‌های خطادار رد و گزارش شوند؛ بدون تأیید چیزی ثبت نشود.
8. خروجی پشتیبان مستقل — فایل خروجی قابل بازگردانی در محیط آزمایشی.
9. ورود Excel محک (فقط‌خواندنی) — اعداد با فایل محک تطبیق کنند؛ هیچ نوشتنی به محک نباشد.
10. داشبورد با اعداد واقعی، سپس محصولات/پیش‌فاکتور/گارانتی — هیچ عدد ثابت نمایشی به‌عنوان واقعی دیده نشود.
11. اتصال GitHub (توسط شما در تنظیمات) و انتشار آنلاین — پس از تأیید شما.

## ۶. نیازمند تأیید مدیر اصلی پیش از تغییر
- فعال‌سازی Lovable Cloud یا استفاده از Supabase شخصی (و پذیرش هزینه).
- انواع مشتری: عمده‌فروش/نمایندگی/مصرف‌کننده یا ترکیب با حقیقی/حقوقی.
- نام برند: «آتا» یا «آترا».
- فهرست نقش‌ها و اینکه چه کسی قیمت تأیید و سفارش لغو می‌کند.
- پاسخ ۴ سؤال باز قوانین سفارش (بازکاری پس از کنترل کیفیت، لغو پس از تحویل جزئی و...).
- نسخه محک و نمونه فایل Excel خروجی آن.
- روش ورود (ایمیل/رمز یا موبایل؛ پیامک هزینه دارد).
- محل نگهداری پشتیبان مستقل و دوره آن.
- اتصال GitHub (کار شما در تنظیمات پروژه).

## جزئیات فنی
- قوانین دسترسی با RLS و جدول `user_roles` جدا؛ تابع‌های سمت سرور با `createServerFn` و احراز هویت.
- مبلغ: `bigint` تومان؛ تاریخ: `date`/`timestamptz` و نمایش با `date-fns-jalali`.
- خواندن Excel در مرورگر با کتابخانه SheetJS و اعتبارسنجی Zod؛ ثبت دسته‌ای پس از تأیید.
- PWA فقط manifest و آیکون؛ بدون service worker.
